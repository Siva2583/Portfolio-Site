02 / PROBLEM

Fluent output can still be wrong.

A language model can return plausible-sounding places, coordinates, JSON, and arithmetic that are not reliable. A travel interface needs to distinguish a useful plan from facts that require verification.

CORE STATEMENT

The model proposes. The application validates, verifies, and computes what it displays.

03 / SYSTEM

Fallback, validate, verify, then enrich.

Voyager requests structured itinerary JSON from a Groq-hosted model chain. If a model is rate-limited, times out, returns invalid JSON, or has the wrong response shape, the server tries the next model. Accepted coordinates from the model are discarded; destination and activity locations are looked up independently.

Implementation detail: the current server prefetches unique category images with Promise.all, then geocodes activities in small batches through a shared 550 ms LocationIQ queue. It does not currently use Promise.allSettled to run both enrichment branches together.

For costs, the model provides per-person values and the client computes group totals from them; the displayed total is not accepted as a free-form model claim. LocationIQ results are checked for word overlap and distance from the destination center.

05 / DECISIONS

Do not trust the convenient field.

  • Validate JSON shape: a non-empty itinerary array is required before model output is accepted.
  • Use an ordered model fallback: HTTP errors, timeouts, malformed JSON, empty content, and invalid response shapes advance to the next model.
  • Discard model coordinates: every activity location is independently geocoded; coordinates from the LLM are not used.
  • Reject plausible-but-wrong matches: location names are checked for word overlap and results beyond 150 km from the destination center are rejected.
  • Throttle geocoder traffic: all LocationIQ lookups share a 550 ms queue and are processed in small batches.
  • Return partial enrichment: a failure during enrichment is caught so the itinerary can still be returned with whatever data was resolved.
  • Keep API credentials server-side: Groq, LocationIQ, and Pexels keys belong in server environment variables, never in the browser bundle.

SAFE FALLBACK

A destination-center pin is less precise than a verified business address, but it is better than a confident, invented coordinate.

07 / CHALLENGES

“Looks real” is not a verification strategy.

Geocoders can return a real but wrong same-name location with no obvious error. The repository documents rejecting weak word-overlap matches, checking distance from the destination center, and falling back to a city-center pin when confidence is insufficient.

Concurrency also has a boundary: image queries are deduplicated and fetched in parallel, while location lookups are throttled to respect provider limits. Combining them into one all-settled enrichment stage would be a separate implementation change, not a current feature.

08 / VALIDATION

Clear gates; modest testing claims.

The server checks the parsed response for a non-empty itinerary array, and geocoding uses name-overlap and distance checks. The project README lists dedicated automated tests for geocoding helper edge cases as future work.

No AI accuracy score, response-time improvement, or complete geocoding test suite is claimed on this page. The interactive panel is local mock data only.
09 / TECHNOLOGY

Model orchestration plus real-data enrichment.

Client: React, Vite, React Router, Leaflet.

Server: Node.js, Express, native fetch, serverless deployment.

Model API: Groq-hosted model fallback chain with JSON response mode and timeouts.

External data: LocationIQ geocoding, Pexels category imagery, CartoDB map tiles.

Result features: day planning, cost aggregation, map display, and print-to-PDF output.

12 / LESSONS

Trust should be earned field by field.

Structured output is a format, not a guarantee. The practical approach is to define which parts can be accepted, which must be recomputed, and which need an external source of truth—and then show a graceful fallback when that source is unavailable.
